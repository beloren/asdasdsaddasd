# Глобальные лидерборды на каждой базе

## Что уже реализовано

На каждой базе автоматически появляется блок из трёх физических досок:

1. `TOP MONEY` — текущий баланс денег игрока.
2. `TOP REBIRTHS` — общее количество ребёртов.
3. `TOP CART DAMAGE` — суммарный фактический урон по тележкам за всё время.

Это глобальные рейтинги между всеми серверами experience, а не список игроков только текущего сервера. Они хранятся в трёх `OrderedDataStore`. Значения публикуются пакетно, а доски обновляются раз в 60 секунд. Первый запрос выполняется примерно через 3 секунды после запуска сервера.

Урон по тележкам засчитывается только когда удар реально снял HP тележки, которую несёт другой игрок. Overkill не считается: если у тележки осталось 5 HP, а кирка наносит 40, рейтинг увеличится только на 5.

## Вариант 1: ничего не моделировать

Можно сразу запустить игру. Если `ReplicatedStorage/Assets/LeaderboardBoards` отсутствует, код сам построит три рабочие тёмные доски с цветными полосами и поставит их на каждую базу.

Если в кастомном `PlotTemplate` нет `LeaderboardMarker`, доски ставятся автоматически у края `PlotPad`. Для готовой карты лучше поставить маркер вручную.

## Вариант 2: своя модель досок

Создай следующую структуру с точными именами:

```text
ReplicatedStorage
└─ Assets
   └─ LeaderboardBoards (Model, PrimaryPart = Root)
      ├─ Root (BasePart)
      ├─ MoneyBoard (BasePart)
      ├─ RebirthBoard (BasePart)
      ├─ CartDamageBoard (BasePart)
      └─ любые декоративные детали
```

Обязательные требования:

1. `LeaderboardBoards` должен быть именно `Model`.
2. У модели обязательно назначь `PrimaryPart`. Рекомендуемое имя этой части — `Root`.
3. `MoneyBoard`, `RebirthBoard`, `CartDamageBoard` должны быть `BasePart`; `MeshPart` тоже подходит.
4. Имена чувствительны к регистру и должны совпадать побуквенно.
5. Все три детали должны находиться внутри `LeaderboardBoards`, можно на любой глубине.
6. Код сам выставляет всем деталям `Anchored = true`, но сохраняет твой `CanCollide`.
7. На декоративных деталях обычно ставь `CanCollide = false`; на стойке или основании можешь оставить `true`.

`SurfaceGui`, заголовки и строки игроков создавать не нужно. Сервер сам создаёт `SurfaceGui` с именем `LeaderboardGui` на трёх обязательных деталях. Если положить собственный объект с таким именем, код заменит его.

## Размеры и ориентация

Рекомендуемый размер каждой лицевой детали: примерно `8 × 10 × 0.5` studs. Текст рисуется на Canvas `700 × 900`, поэтому вертикальное соотношение сторон около `7:9` выглядит лучше всего.

Текст появляется на стороне `Front` каждой детали. В Roblox сторона `Front` смотрит вдоль локального `-Z` этой детали.

Чтобы проверить сторону в Studio:

1. Выбери `MoneyBoard`.
2. Временно добавь на неё `SurfaceGui` с `Face = Front`.
3. Поверни деталь так, чтобы Front смотрел туда, откуда игрок подходит к доске.
4. Повтори для двух других деталей.
5. Удали временные `SurfaceGui`; игровой код создаст свои.

Каждую из трёх деталей можно повернуть отдельно. Главное, чтобы сторона `Front` была обращена к игроку.

## Где поставить доски на базе

Внутри `ReplicatedStorage/Assets/PlotTemplate` добавь обычный `Part`:

```text
PlotTemplate
├─ PlotPad
├─ остальные маркеры
└─ LeaderboardMarker (BasePart)
```

Настройка маркера:

1. Имя: строго `LeaderboardMarker`.
2. Поставь его на землю в точке, где должен находиться `PrimaryPart` модели досок.
3. Поверни маркер так, чтобы блок досок смотрел к игроку.
4. Размер, цвет и прозрачность маркера не важны: код сделает его невидимым и отключит коллизию.
5. Расположи `Root` кастомной модели по центру основания досок на уровне земли. Тогда маркер показывает точное место установки без расчёта высоты.

Если неудобно использовать Rotate, добавь рядом второй `Part` с именем `LeaderboardMarkerLook`. Код направит блок от `LeaderboardMarker` к `LeaderboardMarkerLook`. Обе детали будут скрыты в игре.

`LeaderboardMarker` находится внутри шаблона одной базы. `PlotService` клонирует `PlotTemplate`, модель досок и маркер для каждого участка автоматически. Не нужно вручную копировать доски по карте.

## Обязательные настройки Roblox Studio

Глобальный рейтинг не работает в неопубликованном локальном файле без доступа к DataStore.

1. Опубликуй experience через `File → Publish to Roblox`.
2. Открой `Game Settings → Security`.
3. Включи `Enable Studio Access to API Services` для Studio-теста.
4. Сохрани настройки.
5. Для production используй опубликованный place. В опубликованной игре DataStore API доступен автоматически.

Не тестируй разрушительные операции с production-данными. Для разработки лучше использовать отдельную тестовую копию experience.

OrderedDataStore вручную создавать в Dashboard не нужно. Roblox создаст их при первой успешной записи.

## Настройки в коде

Все параметры находятся в `src/shared/Config.lua`:

```lua
Config.Leaderboards = {
    TopCount = 10,
    RefreshInterval = 60,
    StorePrefix = "PvPExtraction_Leaderboard_01",
    BoardFace = Enum.NormalId.Front,
}
```

- `TopCount` — число строк на каждой доске. Для текущего размера используй `1..10`.
- `RefreshInterval` — период записи и обновления. Не ставь слишком маленькое значение; `60` экономно расходует DataStore budget.
- `StorePrefix` — версия хранилищ рейтинга. После релиза не меняй без причины: новый префикс создаёт новый пустой набор рейтингов.
- `BoardFace` — сторона обязательных деталей, на которой рисуется текст.

## Как проверить деньги и ребёрты

1. Запусти опубликованный place в Studio с включённым API Services.
2. Получи деньги обычной продажей или существующим промокодом.
3. Для ребёрта выполни игровые требования и сделай rebirth.
4. Подожди до 60 секунд.
5. На всех базах должны появиться одинаковые строки рейтинга.
6. Останови тест и запусти его снова: значения должны сохраниться.

`TOP MONEY` показывает текущий баланс, поэтому трата денег или сброс денег при rebirth может опустить игрока в рейтинге. `TOP REBIRTHS` и `TOP CART DAMAGE` только растут.

## Как проверить урон по тележкам

Нужны два игрока, потому что свою тележку игрок не атакует.

1. В Studio открой вкладку `Test`.
2. Установи `Players = 2` и нажми `Start`.
3. Первым игроком возьми тележку.
4. Выведи обоих игроков за безопасную зону базы.
5. Вторым игроком экипируй кирку и атакуй первого.
6. В стандартном `leaderstats` второго игрока `Cart Damage` увеличится сразу.
7. Глобальная доска обновится в следующий цикл, максимум примерно через 60 секунд.
8. Удар внутри безопасной зоны не проходит и статистику не добавляет.

## Сообщения на досках

- `NO PLAYERS YET` — DataStore работает, но в рейтинге ещё нет записей.
- `ENABLE API SERVICES TO LOAD GLOBAL DATA` — запрос не прошёл. Обычно place не опубликован или в Studio выключен API Services.
- `DATASTORE UNAVAILABLE` — Roblox не выдал хранилище при запуске. Проверь Output и состояние Roblox DataStore.

В `Output` ошибки начинаются с `[LeaderboardService]`.

## Финальный чек-лист

1. Experience опубликован.
2. Для Studio-теста включён `Enable Studio Access to API Services`.
3. В `Assets` есть `LeaderboardBoards` либо используется автоматический плейсхолдер.
4. У кастомной модели назначен `PrimaryPart`.
5. Внутри есть три `BasePart` с точными именами.
6. Сторона `Front` каждой доски обращена к игроку.
7. В `PlotTemplate` установлен `LeaderboardMarker` в правильном месте.
8. Тест выполнен с двумя игроками вне safe zone.
9. После ожидания одного цикла все базы показывают одинаковый глобальный Top 10.
10. После перезапуска сервера значения остаются на месте.
